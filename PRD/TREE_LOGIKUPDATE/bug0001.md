## 🔍 FEHLERANALYSE

### Betroffener Code

**Datei:** `app/src/preview3/treeCore.ts`
**Funktion:** `getRootHouseContexts()` (Zeile 280-330)
**Kritische Zeile:** 318

```typescript
const minY = Math.min(...nodes.map((node) => node.y))
const topNodes = nodes.filter((node) => Math.abs(node.y - minY) < 1)  // ← ZEILE 318
```

### Root Cause

Die Filter-Bedingung `Math.abs(node.y - minY) < 1` ist **zu streng**:

1. **Nur Nodes auf exakt der minY-Position** werden als "topNodes" erkannt (Toleranz < 1 Pixel)
2. **Stammväter ohne Eltern** (wie Hador) werden vom Layout-Algorithmus eventuell minimal versetzt positioniert
3. **Folge:** Hador's Node liegt z.B. bei `y: 450.5` während `minY: 450.0` ist → Differenz: `0.5` → **NICHT erkannt als "topNode"**
4. **Ohne "topNode"** wird keine Verbindung zum House Anchor hergestellt

### Warum funktioniert Glóredhel?

| Eigenschaft          | Hador                  | Glóredhel (VORHER)                       |
| -------------------- | ---------------------- | ----------------------------------------- |
| **birth.year** | 410                    | 410                                       |
| **death**      | `null`               | `{"era": "First Age", "year": null}`    |
| **houses**     | `["House of Hador"]` | `["House of Hador", "House of Haleth"]` |
| **Eltern**     | 0 (Stammvater)         | 0 (im Dataset)                            |
| **Y-Position** | ~450.5 (vermutet)      | ~450.0 (exakt)                            |

**Bestätigte Hypothese (Workaround-Test):**

- **Mit Glóredhel:** Ihre Y-Position hat `minY` verschoben → Hador's Node lag knapp daneben → **NICHT erkannt als "topNode"** ❌
- **Ohne Glóredhel:** `minY` wird nur von Hador bestimmt → Hador's Node ist automatisch auf `minY` → **ERKANNT als "topNode"** ✅

**Hypothese:** Glóredhel's Node liegt exakt auf minY, Hador's Node minimal daneben (Rundungsunterschied im Layout-Algorithmus).

## 💡 MÖGLICHE FIXES

### Fix A: Toleranz erhöhen (einfach, aber unsauber)

**Änderung in `treeCore.ts` Zeile 318:**

```typescript
// ALT (zu streng):
const topNodes = nodes.filter((node) => Math.abs(node.y - minY) < 1)

// NEU (toleranter):
const topNodes = nodes.filter((node) => Math.abs(node.y - minY) < 10)
```

**Vorteile:**

- ✅ Einfach umzusetzen
- ✅ Funktioniert sofort für Hador

**Nachteile:**

- ❌ Unsauber (maskiert das eigentliche Problem)
- ❌ Kann andere Nodes fälschlich als "topNodes" erkennen
- ❌ Keine semantische Begründung

**Empfehlung:** ❌ **NICHT EMPFOHLEN**

---

### Fix B: Root-Nodes explizit erkennen (kanonisch korrekt)

**Änderung in `treeCore.ts` Zeile 318:**

```typescript
// ALT:
const topNodes = nodes.filter((node) => Math.abs(node.y - minY) < 1)

// NEU:
const parentIds = new Set(validation.childrenByParent.keys())
const topNodes = nodes.filter((node) => {
  const isRoot = !parentIds.has(node.id)  // ← Keine Eltern = Stammvater
  const isTopRow = Math.abs(node.y - minY) < 1
  return isRoot || isTopRow  // ← Beides ist valide
})
```

**Vorteile:**

- ✅ **Kanonisch korrekt:** Stammväter haben definitionsgemäß keine Eltern
- ✅ **Semantisch begründet:** Root-Status ist eine Eigenschaft der Genealogie
- ✅ **Zukunftssicher:** Funktioniert für alle Stammväter (Bëor, Hador, Haleth, etc.)
- ✅ **Robust:** Unabhängig von Layout-Rundungsfehlern
- ✅ **Workaround bestätigt:** Hador verbindet sich wenn Glóredhel's Y-Position entfernt wird

**Nachteile:**

- ⚠️ Erfordert Zugriff auf `validation` im Filter-Kontext (bereits vorhanden, Zeile 281)

**Empfehlung:** ✅ **BEVORZUGTE LÖSUNG**

---

### Fix C: Layout-Algorithmus fixen (aufwendig)

**Ansatz:** Sicherstellen dass alle Root-Nodes exakt auf der gleichen Y-Position liegen.

**Ort:** Vermutlich `app/src/preview3/layout.ts` oder ähnliche Layout-Berechnung.

**Vorteile:**

- ✅ Behebt die Ursache statt das Symptom

**Nachteile:**

- ❌ Aufwendig zu debuggen
- ❌ Risiko von Side-Effects bei anderen Nodes
- ❌ Rundungsfehler in Float-Berechnungen unvermeidbar

**Empfehlung:** ❌ **NICHT EMPFOHLEN** (zu aufwendig für minimen Gewinn)

## 📝 LESSONS LEARNED

1. **Stammväter brauchen spezielle Behandlung** — sie haben keine Eltern-Relationen und dürfen nicht über Y-Position-Filter aussortiert werden.
2. **Float-Vergleiche sind fehleranfällig** — `< 1` Pixel Toleranz ist zu streng für Layout-Berechnungen mit Rundungsfehlern.
3. **Semantik vor Geometrie** — Root-Status ist eine genealogische Eigenschaft, keine geometrische Position.
4. **Dataset vs. Code** — Nicht alle Probleme liegen im Dataset — manchmal ist die Verarbeitungslogik defekt.
5. **Workarounds können Hypothesen bestätigen** — Der Glóredhel-Workaround hat die Root-Cause-Analyse validiert.
